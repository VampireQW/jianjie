# iPhone AirPlay 接收组件

接收引擎使用 FDH2/UxPlay 源码，固定版本为
ec203121355220dd90278a369eeabb0b8ba4f14a（1.74）。
源码提供内置 mDNS，不安装 Bonjour 系统服务。

## 构建

先按照 ../README.md 准备项目的 Zig 0.15.2 编译器，然后运行：

    python native/airplay/fetch_deps.py
    python native/airplay/build.py

依赖下载到项目 build/airplay-research，不进入主 EXE。
build.py 使用固定源码与 Windows 导入库，生成 receiver.exe、manifest.json、
LICENSE、source.zip。全量 PyInstaller 打包会再次构建接收引擎，携带以上文件及防火墙辅助脚本。

source.zip 包含实际构建使用的 UxPlay 完整源码、修改后的 Windows 主入口、
Windows 时间戳兼容调整和构建脚本。引擎遵循 GPLv3；上游各源文件的许可与版权注释保留。
Windows 的 IPv4 组播 TTL 与回环选项使用 DWORD，并检查 TTL 设置结果；
接收器输出发现接口和实际 TTL，便于定位局域网发现问题。
windows_discovery.py 使用网卡类型、硬件接口标志与媒体连接状态筛选真实 Wi-Fi / 以太网，
避免 VPN / TUN 虚拟接口的地址被当成局域网地址；多个硬件接口可用时参考网关和 IPv4 跃点数。
组播发送与加入成员绑定同一个选中接口，显式绑定失败时不回退到系统默认虚拟网卡。
未找到硬件局域网时明确报告网络未就绪，不在错误的默认网卡上继续显示接收就绪。
windows_video.py 对固定上游源码应用 Windows 窗口及视频链路调整。
接收器嵌入项目的 _app.ico，设置独立 AppUserModelID，视频窗口标题为“简截投屏”，
窗口大小图标使用嵌入资源；只处理接收器自身的视频窗口。
视频窗口的默认大小根据收到的真实画面比例，等比例放大或缩小至所在显示器可用工作区的约 95%，
居中显示，保留任务栏和标题栏空间；在拿到实际画面尺寸前不固定默认大小。
仅首次显示时自动调整，之后用户仍可自由拖动、缩放或切换全屏。
首次画面显示时短暂置顶 2 秒，然后恢复普通窗口层级；用户后续最小化或切换窗口时不会反复拉回。
主程序仅向自己启动的接收器授予前台激活权限，不修改 Windows 全局焦点策略。
GStreamer 内部窗口类使用 ANSI 窗口过程，中文标题相关消息改用 Unicode 默认窗口过程；
其他输入、显示和全屏消息仍交给原窗口过程处理。

## 运行

电脑控制期间，仅投屏画面窗口暂时解除 Windows 输入法上下文关联，让物理按键通过蓝牙交给 iPhone，避免拼音被电脑输入法截留。Esc、F8、Ctrl+Alt+M、失焦、断连及窗口销毁都会恢复原先的上下文；不更改 Windows 全局输入法或用户配置。中文在 iPhone 上选择拼音键盘后输入，Ctrl+空格切换手机输入法，空格选字。Windows 输入法已生成的中文字、电脑剪贴板与表情文本不会通过 HID 自动同步。

媒体运行库从 leapbtw/uxplay-windows 的 2.0.0.1736 版本下载，
SHA-256 固定为 9d3a51c15fc9db857351195e7eb7bbb21700d9ae25d936a54bcf8536b62cca18。
只解压媒体 DLL 与 GStreamer 插件，不运行原包的桌面程序、Bonjour 服务或蓝牙程序。

组件存放在应用数据目录的 mirroring/airplay-1 中，随应用数据目录迁移。
接收器在独立进程中运行，使用私有 DLL 和插件目录。
主程序仅处理连接状态与控制消息，不复制每帧视频。

接收器通过会话专用 Windows 事件正常停止，并监测主程序退出。
主程序关闭或连接窗口关闭后停止该会话；不会结束其他投屏软件的进程。
连接状态写入本地 mirroring/session-status.json，不记录配对码或屏幕内容。

名称、声音开关可配置；配对码每次启动重新生成。
此版提供局域网画面与声音投屏，不提供 iPhone 鼠标反向控制。

默认向手机请求 1080p、最高 60 帧，也可选择 720p 或最高 30 帧。
实际编码尺寸由手机协商决定，接收端在状态中显示收到的画面尺寸。
“优先低延迟”默认开启：关闭时间戳等待、视频显示 processing-deadline 为 0，
使用 d3d11convert 完成颜色转换及缩放，保留 decodebin 自动选择解码器。
私有接收器优先选择 D3D11 硬件解码，与转换、显示保持同一接口；
不支持时保留其他硬件及软件解码回退。
镜像启动不阻塞等待实时 appsrc 的 preroll 或 PLAYING 完成，首包可以及时进入解码器。
会话状态的 codecToFirstSinkMs 记录编解码选择至首个解码帧到达显示端的时间，
这是接收端内部指标，不等于手机点击至屏幕实际呈现的完整时间。
编码队列与 appsrc 有明确上限，低延迟模式仅在解码后丢弃过期帧，避免破坏 H.264 参考帧。
关闭低延迟选项时恢复时间戳声画同步。无线网络和发送端编码仍会带来延迟，不能承诺零延迟。
实际解码器、接收尺寸和窗口图标状态写入会话状态，不保存每帧图像。

防火墙辅助脚本仅允许 receiver.exe 的本地子网入站连接，覆盖专用、域及公用网络。
仅处理同一程序的 Windows 询问规则，保留其他程序规则和公用网络默认入站阻止。


## 仅修改界面时复用原版接收器

默认全量打包仍从固定源码构建。设置 `JJ_AIRPLAY_PREBUILT_RECEIVER` 为已有接收器的完整路径，
可以显式复用已有产物。打包前校验大小、manifest 中的 SHA-256、固定上游提交和干净源码树，
并确认 source.zip 中的所有原生补丁、依赖清单、构建脚本与图标匹配当前文件；任何不一致都会失败。
构建证据写入 build/airplay-package-provenance.json。此模式不改变接收器二进制内容或安全设置。

R290 起启动时先用 manifest 中固定的大小与 SHA-256 校验已安装接收器。通过后直接复用，
不依赖一次性解压目录中的接收器副本。缺失或校验不通过时，仍要求从可信包中校验后安装，
不会启动内容不匹配的文件。
